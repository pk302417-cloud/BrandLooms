# BrandLoom: Product Overview

## The problem

Organisations now publish through many channels at once. Employees, freelancers, agencies and AI writing tools all produce content. Brand guidelines, approved facts and asset libraries exist, but they live in PDFs and wikis that creators rarely reread under deadline pressure.

The result is content that is off-tone, uses the wrong terms, repeats outdated facts, makes claims nobody can support, or uses the wrong logo or colours. These errors are usually found after publication, when credibility is already damaged.

BrandLoom moves the check before publication. It reviews each draft against the organisation's own approved sources, explains every finding, proposes fixes that keep the creator's purpose, and keeps people in control of every decision.

## Users

| User | Today | With BrandLoom |
| --- | --- | --- |
| Content creator (employee, freelancer, agency writer) | Unsure what is on-brand; vague feedback arrives late | Instant check with reasons and optional fixes |
| Brand or marketing manager | Reviews everything by hand; the same mistakes recur | Approval queue, risk-based routing, a clear record of decisions |
| Authorised reviewer (legal, compliance, product) | Receives claims with no sources | Claims arrive flagged, with the approved fact or an "unsupported" status |
| Guideline administrator | Cannot see which rules are ignored or unclear | Source library with owners and expiry dates; recurring-issue reports (planned) |
| Customers and partners (indirect) | Receive misleading or inconsistent messages | Fewer incorrect claims reach them |

## Principles

1. **Grounded or silent.** A finding appears only when it points to an approved source passage. If no source supports a concern, it is shown as a question for a person, never as a rule violation.
2. **Explain, do not reject.** Each finding names the source and the reason, and offers a fix the creator can accept, edit or dismiss.
3. **Humans decide.** The system never publishes, approves or edits silently. Dismissals need a reason. Every action is logged.
4. **Expired facts are not trusted.** A fact past its expiry date is flagged for its owner.

## Workflow

| Step | Who | What happens |
| --- | --- | --- |
| 1. Set up sources | Administrator | Guidelines, terms, approved facts (with owner and expiry) and assets are loaded with versions |
| 2. Submit a draft | Creator | Copy is written or pasted and a channel is chosen |
| 3. Automated review | System | Rule checks run against the approved sources (AI analysis is planned) |
| 4. Read findings | Creator | Each finding shows category, severity, confidence, the flagged text, the reason, the source passage and a suggested fix |
| 5. Resolve | Creator | Each fix is accepted, edited or dismissed; dismissals need a reason |
| 6. Route for approval | Creator | Drafts with dismissed claims or facts go to a Reviewer; others go to a Manager |
| 7. Decide | Manager or Reviewer | Approve, or request changes with a note. The decision, approver and time are logged |
| 8. Learn (planned) | Manager or Administrator | Recurring mistakes and unclear guideline passages are surfaced |

## Demo content

The demo brand, Northwind Outdoor, is fictional. Its guidelines cover tone (G-01), claims (G-02), water-resistance wording (T-01) and product naming (T-02). Its approved facts cover the founding year (F-01), the Ridgeline 40 weight (F-02), recycled content (F-03) and a UK price (F-04), which is deliberately expired so the expiry rule can be seen working.
